# Order-to-Fill Execution Quality Data Pipeline

## 1. Problem Statement
Intraday retail trading desks generate high-frequency buy/sell signals that are routed to brokers for execution. Fragmented logging across signal generators and broker execution books makes it difficult to detect execution degradation, signal-to-fill latency, and hidden slippage costs. This pipeline ingests raw market prices and order execution streams, applies business-oriented data validation, builds a relational transaction model, and calculates actionable execution quality KPIs.

## 2. Target Stakeholders & Users
- **Head of Trading Desk**: Monitors portfolio-level execution degradation and cumulative slippage drag in INR.
- **Trading Operations (Ops)**: Identifies venue-specific exchange throttles, order rejection trends, and latency anomalies.
- **Compliance & Risk Team**: Audits off-market-hours execution flags, price band anomalies, and unlinked orphan orders.

## 3. Primary Project KPI
**Total Slippage Cost (INR)** — The total financial drag in Indian Rupees incurred due to unfavorable price movements between trade signal generation and broker order fill (`slippage_bps / 10000 * fill_price * fill_qty`).

## 4. Data Architecture & Source Overview

![Source Map](file:///c:/Users/amitb/Desktop/Projects/FDE/Assignment-2/diagrams/source_map.png)

| Source Name | System / Vendor | Retrieval Mode | Data Owner | Grain | Known Gaps & Limitations |
|---|---|---|---|---|---|
| Market Prices | yfinance API | REST API / Python Library | Market Data Team | 5-minute OHLC tick `(timestamp, symbol)` | Real exchange data; lacks order book depth and tick-level L2 bid/ask spread. |
| Trading Signals | Algo Desk System | File Ingestion (CSV) | Algo Trading Desk | Single trade signal (`signal_id`) | Synthetic generation based on historical price timestamps. |
| Order / Fill Book | Broker Gateway | File Ingestion (CSV) | Trading Operations | Order lifecycle update (`order_id`) | Synthetic log containing simulated latency noise, partial fills, and corrupt test records. |

> **Documented Data Note**: Market price data is fetched live from exchange feeds via `yfinance`. Signal and order execution logs are synthetically generated because live broker execution API credentials are proprietary and unavailable in dev environments.

## 8. Business Decision Enabled
The output evidence table directly informs trading operations whether to adjust smart order routing (SOR) thresholds, renegotiate execution SLAs with brokers experiencing high `EXCHANGE_THROTTLE` rejection rates (such as ICICIBANK.NS or INFY.NS routing), or flag latency spikes exceeding 4.5 seconds for desk intervention.

## 9. Known / Unknown / Assumptions / Limitations

- **Assumption**: Market data from `yfinance` represents real exchange price context, while order and signal data are simulated to mimic intraday broker feed noise.
- **Known**: Synthetic signal generation introduces controlled latency (0.1s to 4.0s) and random partial fill probabilities to stress-test validation rules.
- **Unknown**: Actual broker-side queue positioning and exchange match engine queue delays on NSE.
- **Limitation**: Slippage cost calculation assumes single fill price per order and does not account for multi-tranche execution splits across different execution venues.
